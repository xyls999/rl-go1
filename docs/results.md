## 3. 跨赛道退化与"环境数依赖"的证据

| 现象 | 证据 |
|---|---|
| 同一 ckpt、同一难度带（0.82–0.85），环境数不同结果剧变 | 1 环境 100 %、4 环境 100 %、16 环境 0 %、256 环境 8.2 %；无 cooking failure，换 seed 仍为 0 % |
| 赛道加长加密后旧策略退化 | 第一层 a9：@1.0 由（短赛道认证内的）≥90 % 降到 36.72 % |
| 网格面数超预算导致"全员摔倒" | 单 tile 62,876 面 → 256 环境 16.1 M 面 → 日志 2 行 `cooking failure` → completion 0 / fallen 1.0；降到 12,716 面（3.3 M）后恢复正常 |
| 未屏蔽的射线未命中把整张几何变成 NaN | 第二层 `_relief_geometry` 对未命中射线（`inf`）做 `inf − inf` → 起伏图全 NaN → 训练在第 50 轮崩（`live relief geometry contains NaN or infinity`）。触发条件：狗靠近网格远端时 5 m 前视探针落到网格外。修法见 `hier_v2/relief.py::relief_map`（`isfinite` 屏蔽 + 分母下限），修复后 2000 轮 0 报错 |
| 生成器内外层阈值不一致会死循环 | 填充阈值外层 −1.8 / 内层 −2.2 → 无限 while（pytest 100 % CPU 卡死）。两处阈值必须一致 |

**结论**：所有报数必须使用 256 环境（与训练批量一致），并确认启动日志中 `cooking failure`
计数为 0，否则结果不可比。
