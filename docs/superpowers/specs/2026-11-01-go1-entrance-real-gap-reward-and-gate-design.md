# Go1 入口真沟奖励与严格 512 环境验收设计

日期：2026-11-01。状态：待用户审阅书面设计；不得据此覆盖线上源码或启动新训练。

## 问题和证据

- V132.1 入口教师使用 `combined_part_entrance`：每块 2–5 条横贯路宽的开口沟，宽 0.08–0.24 m，落脚台 0.65–1.10 m，首障碍距出生点 1.30–3.00 m；沟底低于基准面至少 0.55 m。几何 audit 在四类各 512 块通过，PhysX check 四类各 512 环境通过并恢复 active source。
- 入口运行配置是 512 环境、训练 seed 42、`650` 总迭代（50 次 critic-only + 600 次 actor 更新），速度 0.35–0.8 m/s。Gate seed 2028、计划困难度 0/0.1：147/365 环境，非高难度挤压。
- 当前权重中速度跟踪 3、进度 4、终点 200、沟侵入 −80，逐沟清越 `leap_clear` 权重 1；`supported_short` 0.8、`safe_segment` 6。但 `mixed_reward_segments` 对专用入口全 NaN，`_combined_family_mask` 不含入口，V14 short helper 未启用，所以 650 次迭代日志里两项始终是 0。`takeoff_alignment` 同样全 0；专用入口并非必须起跳，不以强制起跳作修复。
- 训练末期日志 `leap_clear` 约 0.0012，`gap_intrusion` 约 −0.87（日志统计标度），安全短沟的正反馈稀疏；可确认奖励缺口，但不能单凭此证明失败的唯一成因。
- 失败 gate 的 `environments` 有 512 个槽，逐槽完成回合合计 760，成功数 234；顶层却写 `episodes:512`、`completion_rate:0.3078947`，其实际分母是 760。远端 CLI 的覆盖循环允许已完成的快失败环境重复加入，直到每槽都有至少一回合。该报告不符合严格每槽一次的 512 回合协议；入口未达到 90%，原串行队列已停，其他老师未开始。旧权重和报告留存。

## 范围和约束

仅新增隔离版本 V132.2 的入口奖励、验收计数/逐回合遥测与专用训练配置/脚本；线上活动源码仅在独占锁下临时 overlay，退出逐哈希恢复。保持最终 `combined` mesh 不变，专用入口几何的沟宽、条数、沟底、落脚台不变；不放宽碰撞、落沟、稳落、全沟清越和终点判据。Actor 仍为 1073 输入、12 动作、GRU128；不暴露族别或特权沟边界，0.35–0.8 m/s 指令不变。训练与评测匹配观测、奖励和扰动；不启动学生蒸馏、watchdog、自动 p2。

## 方案

1. **真实事件为唯一成功事实**。继续用 `all_gap_segments` 的真沟边界和 V132.1 的 `gap_clearance_step` 维护每沟 `paid` 状态；成功须所有实际沟取得清越信用且无硬失败。逐沟安全着地事件可同时提供一次性 `safe_segment` 增益，不增加第二套可独立刷分的落脚判据。
2. **入口专用稠密引导**。仅对 `combined_part_entrance`，在每条未结算短沟的近侧/远侧安全落脚窗口，奖励有至少两足支撑、直立、非坠沟且沿指令向前的接近；使用真实边界作为 reward-only 元数据，不进入 actor。驻足、反复往返、触碰低沟底、硬碰撞、跌倒、已结算沟和其他家族一律不给增益。初始权重沿用配置的 `supported_short=0.8`、`safe_segment=6.0`，若需调参须在独立试验中单变量对照，不擅自削弱硬判据。保留 `leap_clear` 逐沟事件，记录各项实际生效频次及量级。
3. **严格 gate 与遥测**。给隔离 CLI 增加显式严格模式，按首次完成为每个 env ID 收一条结果；忽略后续同槽完成，直至 512 个不同槽恰好各 1 回合。报告 `episodes=512` 必须与 `sum(environments[*].episodes)=512`、`len(environments)=512` 一致，且每槽 `episodes=1`；不满足则拒绝通过。保留确定性动作、独立 seed、家族分组和原失败统计。启用逐回合 trace，并要求各槽的 `required_gap_count`、`credited_gap_count`、碰撞/跌倒/落沟、完成位置可归属，以区分过沟动作失败与评分漏记。报告与 trace 用新文件名保存，不覆写 seed 2028 的旧证据。
4. **验证节奏**。先写失败测试：专用入口有安全接近正反馈、无支撑/沟底/硬失败/已结算与非入口均无；真实清越事件只付一次；CLI 快失败重复回合不得污染严格 512 分母；缺槽/trace 缺字段拒绝验收。然后在隔离 overlay 跑单测、完整项目测试、四类 512 环境 PhysX smoke、可控事件探针。对原 V132.1 checkpoint 做开发诊断，复核逐回合 trace；不要将开发 seed 当最终 holdout。随后做短规模 A/B 以同地形/初始权重比较信用发生率和失败位置；只有改善证据充分才用新 run ID 续训入口。最终选未使用的新 seed 作一次严格 512 槽 gate，≥90% 才按接沟→长沟→轮胎继续；任一失败立即停止。

## 不采用

- 直接增加 PPO 迭代：不能修复从未生效的短沟奖励与错误分母。
- 缩窄沟、填平沟底、降低硬失败阈值或提前终点：违背真实地形与最终验收。
- 把 `combined` 混合奖励掩码整体扩张到入口：该状态的四行 metadata 对入口全 NaN，且会误改变其他家族。

## 完成判据与风险

必须从新日志正面看到入口专用引导和真实逐沟信用非零、失败/沟底不得计分，严格 512 槽各一次及完整 trace，校验 checkpoint、配置、源码哈希和 GPU/锁恢复。90% 只代表专用入口 gate，绝非混合接力、最终同批 512 环境 11 族各≥90% 或实机安全认证。若小试仍因碰撞/跌倒主导失败，应先用 trace 归因，不叠加多个奖励改动盲训。
